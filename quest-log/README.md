# 人生任务局 · Questlog

手机和电脑可访问的游戏式任务日志。静态前端不依赖构建工具。

## 已实现

- 主线 / 支线，任务领域、优先级、状态和难度。
- 每日任务：独立导航与总览入口，新增 / 编辑 / 删除，每天打卡；北京时间零点自动开启新一天。
- 每日完成获得 50 XP，同日重复打卡不会叠加；连续天数、近七天记录、累计次数与历史经验保留。
- 主线拆步骤，支线关联主线；完成 / 重新开启 / 编辑 / 删除。
- DDL 精确到分钟、临期与逾期提示、截止时间轴。
- 今日聚焦最多三项。
- 经验、等级、三种成就、完成记录和自定义奖励。
- 当前浏览器持久保存，跨标签页修改冲突保护。
- JSON 导入 / 导出；ICS 日历导出，UTF-8 正确折行。
- 初次打开为明确标记的示例存档，可清空示例开启个人存档。

## 当前同步状态

已连接专用 Supabase 项目 `questlog`。打开 https://gxlewish44.github.io/FUJIAN/quest-log/ ，在“存档与同步”注册邮箱账号，确认邮件后登录。手机和电脑使用同一任务局账号即可同步；此账号与 Supabase 管理控制台账号独立。

修改立即保存到浏览器，约 0.9 秒后自动上传。页面可见时每 20 秒检查云端，回到页面或网络恢复也会检查。需要先联网打开页面；未启用离线应用缓存。示例不会上传。离线修改保留在本机，网络恢复后重试。不要在备份或同步前清理浏览器数据。

两台设备同时编辑时不会自动合并或覆盖；请导出备份，再通过“用云端替换本机”或“用本机替换云端”选择保留的版本。编辑任务时暂停自动读取。换账号时不会自动上传旧账号存档，需要明确选择。会话与存档只保存在浏览器及用户自己的云端行中。

`supabase.sql` 已在真实项目执行；RLS、权限、匿名拒绝、两个事务内测试账号的隔离、所有权变更拒绝和原子版本冲突均通过 `test-database.sql` 验证（测试数据已回滚）。`supabase-hardening.sql` 收紧 Supabase 默认自动 RLS 事件函数的 API 执行权限。

每日任务采用兼容的 `dailies` 存档字段，旧存档默认空列表。每日模板和打卡历史与主支线一同同步、导入和导出。升级时运行 `supabase-daily-upgrade.sql`，避免之前打开的旧客户端丢弃每日记录；旧客户端会被提示刷新。每日任务不混入单次任务的 DDL 日历，漏打卡不扣分，删除任务会删除其历史及对应经验，界面会确认。

站点 URL 与确认邮件跳转地址已配置。`config.js` 只有项目 HTTPS 地址和 publishable 公钥。默认邮件服务有速率与收件人限制，个人使用请优先使用项目所属邮箱；扩大使用范围前配置自己的 SMTP。真实用户需自行完成首次注册及邮箱确认。

## 本地运行

在此目录运行 `python -m http.server 4187 --bind 127.0.0.1`，打开 http://127.0.0.1:4187/。

## 任务编辑、成就和每日文案

主线、支线、已完成任务以及每日任务卡均有“编辑”按钮；编辑保存沿用现有存档和自动同步。成就共 20 项，从现有任务、步骤、经验和每日打卡记录计算；连续打卡采用单项任务的历史最长连续天数。取消打卡、重新开启或删除记录会重新计算相关进度，不额外发放经验。

页面标题、提示、侧栏短句和页脚按北京时间日期每日轮换；同日跨设备显示一致。预置文案无需额外服务，页面打开时每分钟检查，并在回到页面时检查换日。编辑窗口打开时会等待关闭后更新。
